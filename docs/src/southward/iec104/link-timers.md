## 1. 定时器与确认层次

主机字段允许 IPv4、IPv6（含方括号/作用域）和带可选末尾根点的 ASCII 主机名；展示值最多 254 字节。表单预筛选不会替代服务端地址校验。

| 字段 | 默认值 | 实际职责 |
| --- | --- | --- |
| `t0Ms` | `10000` | 地址解析与全部候选 TCP 连接共享的端点建立期限 |
| `t1Ms` | `15000` | 最老未确认 I 帧，以及 STARTDT/STOPDT/TESTFR 等 U 帧的链路确认期限 |
| `t2Ms` | `10000` | 收到尚未确认 I 帧后的 S-ACK 聚合期限 |
| `t3Ms` | `20000` | 空闲时发起 TESTFR 链路测试 |

`t0Ms` 不是全部应用握手期限。TCP 建立后的 U 帧确认由 t1 管理；S/I 链路 ACK 也不能代替 GI/CI 或控制的 ACT_CON/ACT_TERM。

应用请求保留自己的原始截止时间。排队、一次链路 ACK、选择确认或重连不会续期。对端保持健康的链路但不返回应用确认时，仍可能得到结果未知。

## 2. k/w 与序号

- `kWindow` 默认 `12`，限制实际完成发送、尚未被对端有效确认的 I 帧数；范围为 `1..32767`。
- `wThreshold` 默认 `8`，收到该数量的 I 帧或达到 t2 时需要发送确认；范围为 `1..kWindow`。
- 所有定时器必须非零，且 `t2Ms < t1Ms`。配置校验拒绝无效组合。
- 15-bit 序号按协议回绕。无效/超前 ACK 不释放未完成发送的额度；链路到期也不制造确认。

较大 k 允许更多在途帧，也增加积压与持额。根据设备 profile、实际往返时间、失败率和占用选择参数，不用扩大窗口掩盖未完成确认。断链后的控制不会自动重发整个原操作。

## 3. 出站队列与字节保护

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `sendQueueCapacity` | `1024` | 有界出站请求队列；控制/召唤还有原生工作预留与目标占用 |
| `maxPendingAsduBytes` | `1048576` | 出站待发/在途 ASDU 字节约束，也用于各自控制/召唤的工作预留 |
| `discardLowPriorityWhenWindowFull` | `true` | 窗口满时丢弃低优先级出站请求 |
| `mergeLowPriority` | `true` | 未启用上述丢弃时，合并低优先级出站请求为最后一项 |
| `lowPrioFlushMaxAgeMs` | `2000` | 低优先级合并项的刷新年龄；`0` 关闭年龄触发 |
| `tcpNodelay` | `true` | TCP_NODELAY |

队列数量至少为 `1`，待发字节容量至少为原生 I 帧包络的 `12` 字节；二者均不能超过当前构建 metadata 给出的上限。超限配置在提交前拒绝，保持旧 revision 和连接；上限不表示已经为该容量分配或预留内存。合法但很低的容量仍可能使具体请求因额度不足被拒绝；这和超限配置错误是不同结果。

这些低优先级策略针对出站请求，不是上送遥测的合并/保留承诺。高优先级控制不能靠丢弃或合并伪称完成；队列/预算拒绝和已发送但结果未知必须分别处理。

同名额度不代表一个全进程共享内存上限。入站 ASDU、Core 样本/缓存、北向队列和基础设施各有自己的边界与观测。不要把此参数解释为“上送洪峰的总内存上限”，也不要用 RSS 代替业务持额。

## 4. 观察与调参

分别观察关联状态、链路 ACK、应用接受/终结、独立采集质量、入站丢弃诊断及队列/字节拒绝。只读召唤结束不保证所有样本已进入 Core。`dataSilenceTimeoutSecs` 检查过程信息活动；链路保活正常不能证明过程数据仍在更新。

需要调整定时器/窗口时，按实际设备 profile 和观测确定，并保留原操作身份。超时/未知不能靠延长原截止时间、重连或创建新意图重发来“恢复成功”。
